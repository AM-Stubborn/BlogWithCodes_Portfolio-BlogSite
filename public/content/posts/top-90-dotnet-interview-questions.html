This is my personal cheat sheet of 90 interview questions I expect for Senior Software Engineer roles on the stack I ship day to day: C#, OOP, and ASP.NET Core. Answers are short — enough to speak for 60–90 seconds, then deepen with a real project example.

How I use this list: pick 10 questions a day, answer out loud, then map one answer to something I actually built (.NET API, EF Core, JWT, Azure-hosted service).

1. OOP (Q1–Q20)

Q1. What are the four pillars of OOP?
Encapsulation, Abstraction, Inheritance, Polymorphism. Be ready with a one-line definition and one code/story example for each.

Q2. What is encapsulation?
Bundling data and behavior, hiding internal state behind well-defined APIs (properties, methods). Prevents invalid state and reduces coupling.

Q3. What is abstraction?
Exposing only what callers need. In C#: abstract classes, interfaces, and high-level services that hide EF/HTTP details.

Q4. What is inheritance?
A derived type reuses and extends a base type. Prefer composition when inheritance creates fragile hierarchies.

Q5. What is polymorphism?
Same interface, different behavior — method overriding, interface implementations, and sometimes operator overloading.

Q6. Abstract class vs interface?
Abstract class: shared state + implementation, single inheritance. Interface: contract (can have default interface methods), multiple implementation. Prefer interfaces for boundaries; abstract classes for shared base behavior.

Q7. Method overloading vs overriding?
Overloading: same name, different signatures (compile-time). Overriding: replace base virtual/abstract method in derived type (runtime).

Q8. What is composition over inheritance?
Build behavior by combining objects (DI services) instead of deep class trees. Easier to test and change.

Q9. What is cohesion and coupling?
High cohesion: a type does one job well. Low coupling: types depend on abstractions. Senior interviews love this framing.

Q10. What is SOLID? Name each letter.
Single Responsibility, Open/Closed, Liskov Substitution, Interface Segregation, Dependency Inversion.

Q11. Explain Single Responsibility with an API example.
A controller should not also send emails, write SQL, and format PDF. Split into services with clear ownership.

Q12. Explain Open/Closed.
Open for extension, closed for modification — add new strategies/handlers without rewriting core paths.

Q13. Explain Liskov Substitution.
Derived types must honor base contracts. If a subclass breaks expectations (throws unexpectedly, weakens invariants), LSP is violated.

Q14. Explain Interface Segregation.
Prefer small focused interfaces over one fat interface that forces unused methods.

Q15. Explain Dependency Inversion.
High-level modules depend on abstractions; concrete implementations are injected (ASP.NET Core DI).

Q16. Association vs aggregation vs composition?
Association: uses. Aggregation: has-a, parts can live independently. Composition: strong ownership; parts die with the whole.

Q17. What is a design pattern? Name 5 you use.
Reusable solution to a recurring design problem. Examples: Repository, Factory, Strategy, Decorator, Mediator/CQRS-style handlers, Singleton (carefully).

Q18. When is Singleton a bad idea?
Hidden global state, hard testing, concurrency bugs. Prefer DI with a carefully chosen lifetime.

Q19. What is the Strategy pattern?
Swap algorithms behind a common interface (payment providers, discount rules, auth schemes).

Q20. What is the Decorator pattern in .NET?
Wrap an implementation to add behavior (logging, caching, retries) without changing the core class — also how middleware layers work conceptually.

2. C# language & runtime (Q21–Q55)

Q21. Value types vs reference types?
Value types store data (structs, primitives); reference types store a reference to heap data (classes, arrays, delegates). Affects copy semantics and GC pressure.

Q22. Stack vs heap (practical view)?
Locals/value storage vs managed objects. Don’t over-simplify — focus on allocation cost and lifetime.

Q23. Boxing and unboxing?
Boxing: value type → object/interface (heap allocation). Unboxing: reverse with cast. Avoid in hot paths.

Q24. const vs readonly?
const: compile-time constant. readonly: set in declaration or constructor (runtime). Static readonly for shared immutable config.

Q25. ref vs out vs in?
ref: pass by reference, must be assigned before. out: must be assigned inside method. in: readonly by-ref to avoid copies of large structs.

Q26. == vs Equals vs ReferenceEquals?
== can be overloaded; Equals is virtual/overridable; ReferenceEquals checks same instance. For strings, value equality is common.

Q27. String vs StringBuilder?
Strings are immutable; repeated concatenation allocates. StringBuilder for many mutations in loops.

Q28. string.IsNullOrEmpty vs IsNullOrWhiteSpace?
Empty checks null/""; WhiteSpace also treats spaces/tabs/newlines as empty for user input.

Q29. What are nullable reference types?
Compiler annotations (?) to reduce NullReferenceException. Enable nullable context and treat warnings seriously.

Q30. What is a record / record struct?
Immutable-friendly types with value-based equality (for records). Great for DTOs and messages.

Q31. class vs struct?
Class: reference type, inheritance. Struct: value type, no inheritance from other structs/classes (except interfaces), prefer small immutable data.

Q32. What is a sealed class?
Cannot be inherited. Signals intentional final type; can help JIT/devirtualization in some cases.

Q33. What is a static class?
Cannot be instantiated; only static members. Useful for helpers — avoid hiding dependencies that should be injected.

Q34. Access modifiers in C#?
public, private, protected, internal, protected internal, private protected. Know assembly boundaries for internal.

Q35. What is an extension method?
Static method on a static class with this first parameter. Looks like instance method. Don’t overuse for core domain logic.

Q36. Delegates, Action, Func, Predicate?
Delegates are type-safe method references. Action returns void; Func returns a value; Predicate<T> returns bool.

Q37. Events vs delegates?
Events wrap delegates with restricted subscribe/unsubscribe from outside — safer pub/sub on a type.

Q38. What is LINQ?
Language-integrated query over collections and providers (EF). Prefer clear queries; watch deferred execution.

Q39. Deferred execution in LINQ?
Many operators run only when enumerated. Multiple enumerations can re-run work or hit the DB again.

Q40. IEnumerable vs IQueryable?
IEnumerable: in-memory iteration. IQueryable: expression tree — provider (EF) can translate to SQL. Don’t switch to IEnumerable too early (client evaluation).

Q41. List vs array vs Dictionary?
Array: fixed size. List: dynamic array. Dictionary: O(1) average lookup by key. Choose by access pattern.

Q42. What is yield return?
Builds an iterator without allocating a full collection up front. Streaming style enumeration.

Q43. Exception handling best practices?
Catch specific exceptions, don’t swallow, use throw; to preserve stack, fail fast on unexpected bugs, map to problem details in APIs.

Q44. throw vs throw ex?
throw; keeps original stack trace. throw ex; resets it — usually wrong for rethrow.

Q45. What is async/await?
Non-blocking asynchronous programming model. Methods return Task/ValueTask; await yields until completion without blocking a thread (I/O bound).

Q46. Why avoid async void?
Exceptions are hard to observe; mainly for event handlers. Prefer async Task.

Q47. ConfigureAwait(false) — when?
In library code to avoid capturing SynchronizationContext. In ASP.NET Core apps it’s often less critical than in UI apps — know the reason.

Q48. Task.Run — when is it wrong?
Don’t wrap already-async I/O in Task.Run just to “make it async.” Use it for CPU-bound work off the request thread carefully.

Q49. Deadlocks with async?
Classic: blocking on .Result/.Wait() while a context waits for the same thread. Prefer async all the way.

Q50. What is the Garbage Collector?
Manages heap memory in generations (0/1/2 + LOH). Minimize allocations in hot paths; dispose unmanaged/native resources.

Q51. IDisposable and using / await using?
Deterministic cleanup for resources (streams, DB connections, HttpClient factories aside). Prefer using scopes.

Q52. What is reflection? Pros/cons?
Inspect/invoke types at runtime. Powerful for frameworks; slower and can break trimming/AOT — use sparingly in app code.

Q53. Generics — why?
Type-safe reusable code without boxing (for value types in many cases) and clearer APIs (List<T>, repositories).

Q54. Covariance and contravariance (simple)?
IEnumerable<out T> is covariant; Action<in T> is contravariant. Explains why assignment between generic interfaces works in some directions.

Q55. What are attributes in C#?
Metadata markers ([Authorize], [Required], [HttpGet]). Read by runtime/frameworks via reflection.

3. ASP.NET Core & Web APIs (Q56–Q90)

Q56. ASP.NET Core vs classic ASP.NET?
Core is cross-platform, high-performance, modular middleware pipeline, built-in DI, side-by-side versions — preferred for modern APIs.

Q57. What is the middleware pipeline?
Ordered components that handle requests/responses (exception handling, auth, routing, endpoints). Order matters.

Q58. How do you write custom middleware?
Class with InvokeAsync(HttpContext, RequestDelegate) or inline app.Use. Register in the correct position in Program.cs.

Q59. Controllers vs Minimal APIs?
Controllers: familiar MVC style, filters, conventions. Minimal APIs: lighter endpoints, great for small services. Both are valid — justify choice.

Q60. What is dependency injection in ASP.NET Core?
Built-in IoC container registers services and injects them into constructors. Enables testability and DIP.

Q61. Singleton vs Scoped vs Transient?
Singleton: one per app. Scoped: one per request. Transient: new every time. Never inject scoped into singleton (captive dependency).

Q62. What is a captive dependency?
Longer-lived service holds a shorter-lived dependency (e.g., singleton holding scoped DbContext) — causes bugs. Fix lifetimes or use factories.

Q63. How does routing work?
Endpoint routing matches URL/method to an action/endpoint. Attribute routing ([Route], [HttpGet]) is common in APIs.

Q64. Model binding and validation?
Framework maps query/route/body to parameters. DataAnnotations / FluentValidation + ModelState / automatic 400 responses.

Q65. What are filters / endpoint filters?
Cross-cutting logic around actions (authorization, caching, logging). Prefer middleware for pipeline-wide concerns; filters for MVC/endpoint specifics.

Q66. Configuration in ASP.NET Core?
appsettings.json, environment variables, user secrets, Azure Key Vault providers. Options pattern (IOptions<T>) for typed config.

Q67. Environments (Development/Staging/Production)?
ASPNETCORE_ENVIRONMENT switches config and middleware (Swagger only in Dev, stricter errors in Prod).

Q68. What is Kestrel?
Cross-platform web server for ASP.NET Core. Often behind IIS/Nginx/Azure reverse proxy in production.

Q69. REST principles you follow?
Resource-oriented URLs, correct HTTP verbs/status codes, stateless requests, consistent error shape (Problem Details).

Q70. Common HTTP status codes you use?
200/201/204, 400 validation, 401 unauthenticated, 403 forbidden, 404, 409 conflict, 429, 500. Don’t return 200 for failures.

Q71. Idempotency — why does PUT/DELETE matter?
Safe retries. PUT/DELETE should be idempotent; POST often is not — design carefully for payments/orders.

Q72. Authentication vs authorization?
Authentication: who are you? Authorization: what can you do? JWT/OIDC for identity; policies/roles/claims for access.

Q73. How does JWT auth work in ASP.NET Core?
Client sends Bearer token; middleware validates signature/expiry/issuer/audience; claims populate HttpContext.User; [Authorize] enforces.

Q74. Where do you store JWT on the client? Risks?
Memory preferred for SPAs when possible; localStorage XSS risk; HTTP-only cookies need CSRF strategy. Discuss trade-offs honestly.

Q75. What is CORS and when do you need it?
Browser security for cross-origin API calls from SPAs. Configure allowed origins/methods/headers — never * with credentials in prod.

Q76. How do you secure Web APIs?
HTTPS, authn/authz, input validation, output encoding where needed, secrets in Key Vault, rate limiting, least privilege DB accounts, security headers.

Q77. What is Entity Framework Core?
Microsoft ORM for .NET — map classes to tables, LINQ to SQL, migrations, change tracking.

Q78. Code-First vs Database-First?
Code-First: model + migrations drive schema (common for new apps). Database-First: scaffold from existing DB. Know both conversations.

Q79. What is change tracking? When AsNoTracking?
EF tracks entity instances for updates. Use AsNoTracking() for read-only queries — faster, less memory.

Q80. How do you avoid N+1 queries?
Eager load with Include/ThenInclude, projection to DTOs, or explicit joins. Profile SQL in logs/Insights.

Q81. SaveChanges vs transactions?
SaveChanges uses a transaction by default. Multi-SaveChanges or multi-resource work needs explicit transactions / Unit of Work discipline.

Q82. DbContext lifetime?
Typically scoped per request. Don’t keep one DbContext as singleton. Dispose via DI scope.

Q83. Repository pattern with EF Core — yes/no?
Useful as an app boundary; avoid empty wrappers that just hide DbSet. Prefer clear application services + EF where team agrees.

Q84. How do you version APIs?
URL versioning (/v1), header, or query. Pick one strategy; document breaking changes for product clients.

Q85. Logging vs Application Insights?
ILogger for structured logs; App Insights/OpenTelemetry for traces, metrics, dependency tracking across Azure.

Q86. How do you handle global errors in APIs?
Exception middleware / filters producing ProblemDetails; don’t leak stack traces in production; correlate with request IDs.

Q87. What is Health Checks middleware?
Endpoints for readiness/liveness (DB, dependencies) used by orchestrators and load balancers.

Q88. How do you call external HTTP APIs correctly?
IHttpClientFactory, typed clients, timeouts, retries (Polly) with care, never new HttpClient per call without understanding socket exhaustion.

Q89. Background work in ASP.NET Core?
IHostedService / BackgroundService for queues and scheduled jobs. Don’t run long CPU work directly on request threads.

Q90. How do you prepare a .NET API for production on Azure?
Config via app settings + Key Vault, CI/CD, HTTPS, insights/logging, health checks, scaling (App Service/VMs), secrets/RBAC, zero-downtime deploy mindset, and clear ownership of failures.
